# API mercury-proxy

mercury-proxy — обязательный посредник между Home Assistant и счётчиком:
интеграция обращается только к его HTTP API и не работает ни с портом, ни
с TCP/IP-интерфейсом самого счётчика напрямую. К прокси счётчик подключается
по RS-485/CAN через последовательный порт или по TCP/IP — API от этого
не меняется.

Описание получено запросами к работающему прокси по адресу
`http://hm.webtoucher.ru:5054`. Прокси — тонкая HTTP-обёртка над
библиотекой [mercury-base](https://github.com/webtoucher/mercury-base):
имя команды в пути совпадает с именем метода драйвера протокола
(`mercury_base.mercury_v1` для однофазных счётчиков).

## Общее

- Авторизация: заголовок `Authorization: Bearer <токен>`.
- Формат ответа: JSON. Успех — `{"result": ...}`, ошибка — `{"error": "..."}`
  вместе с кодом HTTP.
- Параметры команды передаются строкой запроса `?params=<байт>`, одним
  значением на параметр. Составные команды (например, суточный срез
  `get_daily_energy_slice`, которому нужны четыре байта) через прокси
  отвечают `500 internal error` — их поддержка в прокси не проверялась.

## Эндпоинты

| Метод и путь | Назначение | Ответ |
| --- | --- | --- |
| `GET /v1.0/` | Название и версия API | `{"name": "mercury-proxy", "api": "1.0"}` |
| `GET /v1.0/health` | Проверка живости | `{"status": "ok", "meters": 1}` |
| `GET /v1.0/meters` | Список подключённых счётчиков | `{"meters": [...]}` |
| `GET /v1.0/meters/<серийный номер>` | Паспорт счётчика | объект счётчика |
| `GET /v1.0/meters/<серийный номер>/<команда>` | Команда драйвера | `{"result": ...}` |

Объект счётчика:

```json
{
  "serial_number": 37793503,
  "model": "206",
  "firmware_version": "1.0",
  "date_of_manufacture": "2015-04-06",
  "meter_version": null,
  "features": ["RS485", "relay"],
  "port": "/dev/ttyACM0"
}
```

## Коды ответов

| Код | Тело | Когда |
| --- | --- | --- |
| `200` | `{"result": ...}` | команда выполнена |
| `400` | `{"error": "unknown path: ..."}` | нет такого маршрута |
| `401` | `{"error": "unauthorized"}` | токен не передан или не подошёл |
| `404` | `{"error": "meter <номер> is not connected"}` | счётчика нет на прокси |
| `404` | `{"error": "mercury_base.mercury_v1 has no '<имя>' command"}` | у протокола нет такой команды |
| `500` | `{"error": "internal error"}` | ошибка внутри прокси |

## Команды, которые использует интеграция

| Команда | Результат | Пример |
| --- | --- | --- |
| `get_energy_accumulators` | тарифные аккумуляторы активной энергии, кВт·ч | `[13159.33, 0.0, 0.0, 0.0]` |
| `get_tariffs_count` | число тарифов счётчика (1…4) | `1` |
| `get_vcp` | напряжение (В), ток (А) и мощность (кВт) в нагрузке | `{"voltage": 233.5, "current": 2.11, "power": 0.315}` |
| `get_mains_parameters` | частота сети, тариф и флаги качества | `{"frequency": 50.01, "tariff": 0, "current_imbalance": false, "reverse_energy": false}` |
| `get_is_relay_on` | включено ли реле | `true` |
| `get_archive_type` | глубина архивов: `2` — есть получасовки, то есть профиль мощности | `2` |
| `get_last_cover_open_datetime` | время последнего вскрытия крышки; без электронной пломбы отвечает `500` | `"2022-11-27 21:42:45"` |

Поле `model` в паспорте — только номер, `"206"`. Буквы оснащения, которые
печатают в заводском обозначении (`206 [P] [R|C|L] [S] [N] [O] [Fx]`),
прокси не отдаёт, поэтому интеграция собирает их из `features` и двух
команд выше.

Полный список команд однофазного протокола — в
[описании mercury_base.mercury_v1](https://github.com/webtoucher/mercury-base/tree/master/mercury_base/mercury_v1):
`get_serial_number`, `get_info`, `get_datetime`, `get_tariff`,
`get_power_limit`, `get_month_energy_slices` (с `?params=0…11`),
`get_reactive_energy_accumulators`, журналы событий и другие.

## Замечания по транспорту

- Прокси на порту 5054 отвечает по **обычному HTTP**. Запрос по `https`
  к этому порту приводит к ошибке TLS (`WRONG_VERSION_NUMBER` у Python,
  `SEC_E_INVALID_TOKEN` у Schannel-клиента curl), поэтому адрес интеграции
  задаётся со схемой `http://`.
- Сервер отдаёт `Server: BaseHTTP/0.6 Python/3.11.2` и не поддерживает
  `OPTIONS`, то есть запросы идут строго последовательно — параллельный
  опрос только создаёт очередь, а не ускоряет его.
- Драйвер `mercury_v1` только читает: `set_relay_on`, `set_relay_mode` и
  `set_relay` отвечают `404 ... has no '<имя>' command`, поэтому реле из
  Home Assistant не переключается — интеграция показывает только его
  состояние и режим (`get_relay_mode`).
