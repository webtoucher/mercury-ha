# Инкотекс Меркурий для Home Assistant

Интеграция для счётчиков электроэнергии Инкотекс Меркурий: активная энергия и
тарифы, мгновенная мощность, напряжение, ток и частота сети в Home Assistant, в
том числе в разделе «Энергия».

## Как это работает

Счётчик опрашивает сервис
[mercury-proxy](https://github.com/webtoucher/mercury-proxy) — отдельная
программа или аддон, которая держит шину счётчика и отдаёт показания по HTTP.
Интеграция обращается только к его REST API.

```
счётчик ── RS-485/CAN или TCP/IP ── mercury-proxy ── HTTP ── Home Assistant
```

К прокси счётчик подключается по RS-485 или CAN через последовательный порт
либо по TCP/IP, если у модели есть сетевой интерфейс. Прямого подключения к
счётчику у интеграции нет: без mercury-proxy она не работает ни с
последовательным портом, ни с TCP/IP-интерфейсом самого счётчика, ни с
оптической головкой.

Прокси не занимает шину монопольно: на порту 5054 у него REST API для
интеграции, на порту 5053 — TCP-шлюз для конфигуратора Инкотекс, поэтому
конфигуратор может подключаться к счётчику параллельно с опросом из Home
Assistant.

## Требования

- Home Assistant 2025.1 или новее.
- mercury-proxy с REST API `/v1.0` — аддон из репозитория
  [hassio-addons](https://github.com/webtoucher/hassio-addons) или сервис со
  страницы [mercury-proxy](https://github.com/webtoucher/mercury-proxy).

## Установка

### Marketplace

1. **Настройки → Marketplace**. Раздел доступен только администратору; при
   первом входе примите предупреждение о стороннем коде.
2. В правом верхнем углу — **Add from link** (добавить по ссылке).
3. В поле **GitHub link** введите `https://github.com/webtoucher/mercury-ha`
   и нажмите **Add**: тип «Интеграция» Marketplace определит сам.
4. Откройте репозиторий в списке и нажмите **Install**.

Репозитории по ссылке Marketplace читает с GitHub, поэтому попросит подключить
учётную запись — доступ только на чтение публичных данных. После установки
перезапустите Home Assistant, если он об этом попросит, и добавьте интеграцию:
**Настройки → Устройства и службы → Добавить интеграцию → Инкотекс Меркурий**.

Обновления появляются в **Настройки → Обновления** вместе с обновлениями Home
Assistant.

### Вручную

Скопируйте папку `custom_components/mercury_proxy` в `custom_components`
вашего каталога конфигурации и перезапустите Home Assistant.

## Настройка

**Настройки → Устройства и службы → Добавить интеграцию → Инкотекс Меркурий**:

1. Адрес прокси. Поле предзаполнено `http://localhost:5054`: это верный
   вариант, когда прокси и Home Assistant на одном хосте. Если прокси в другом
   месте, укажите его адрес, например `http://192.168.1.10:5054`; схему можно
   не писать — подставится `http://`.
2. Токен доступа — тот же, что в заголовке `Authorization: Bearer …`.
3. Счётчик, если к прокси подключено больше одного.

Период опроса меняется в настройках записи: по умолчанию 60 секунд, допустимо
от 10 до 3600. Если прокси перестанет принимать токен, Home Assistant попросит
ввести новый и переиспользует запись.

## Что появляется в Home Assistant

Одно устройство на каждый счётчик. В карточке устройства указано заводское
обозначение модели, например «Mercury 206 PRNO». Подписи сущностей переводятся
на язык интерфейса, а `entity_id` собираются из латинского имени устройства и
номера счётчика, поэтому не зависят от языка:

| Сущность | `entity_id` | Единица | Назначение |
| --- | --- | --- | --- |
| Активная энергия | `sensor.mercury_<номер>_active_energy` | кВт·ч | сумма тарифных аккумуляторов, растёт монотонно |
| Тариф N | `sensor.mercury_<номер>_tariff_1` … `_tariff_4` | кВт·ч | накопленная энергия тарифа, только при нескольких тарифах |
| Мощность | `sensor.mercury_<номер>_power` | кВт | мгновенная мощность в нагрузке |
| Напряжение | `sensor.mercury_<номер>_voltage` | В | напряжение в нагрузке |
| Сила тока | `sensor.mercury_<номер>_current` | А | ток в нагрузке |
| Частота сети | `sensor.mercury_<номер>_mains_frequency` | Гц | частота в сети |
| Реле | `binary_sensor.mercury_<номер>_relay` | — | включено ли реле (только если оно есть у счётчика) |

Сенсор активной энергии помечен `device_class: energy` и
`state_class: total_increasing`, поэтому раздел «Энергия» принимает его как
потребление из сети. Как добавить счётчик на панель — в разделе
[«Энергия»](#раздел-энергия).

## Тарифы

Число тарифов интеграция спрашивает у счётчика при запуске: их может быть от
одного до четырёх (день, ночь, пик). Если тарифов больше одного, на каждый
создаётся сенсор «Тариф N» — его тоже можно добавить в раздел «Энергия», чтобы
считать стоимость по разным тарифам. При единственном тарифе отдельный сенсор
не создаётся: сумма и есть тариф.

## Раздел «Энергия»

Атрибуты сенсоров уже подходят для панели: у активной энергии
`device_class: energy` и `state_class: total_increasing`, у мощности — `power`
и `measurement`. Править конфигурацию не нужно.

1. Откройте **Настройки → Дашборды → Энергия**
   (*Settings → Dashboards → Energy*).
2. В блоке потребления из сети (**Electricity grid**) нажмите **Add grid
   connection** и в поле статистики выберите
   `sensor.mercury_<номер>_active_energy`. Показываются только подходящие
   сенсоры: те, что не пишутся в историю или имеют другую единицу, в список не
   попадают.
3. Цену за кВт·ч задайте в том же окне — числом или сущностью, которая ведёт
   суммарную стоимость. Своего сенсора стоимости интеграция не создаёт:
   счётчик цену не знает.
4. Если тарифов несколько, добавьте ещё по одному подключению на каждый
   `sensor.mercury_<номер>_tariff_N`: у подключения одна цена, поэтому панель
   посчитает расход и стоимость по тарифам отдельно. При единственном тарифе
   хватит общей активной энергии.
5. Чтобы видеть на панели мощность в реальном времени, выберите в поле
   **Type of power measurement** сенсор `sensor.mercury_<номер>_power`. Он
   измеряет весь счётчик, поэтому в подключениях используется только один раз —
   обычно в том, где указана общая активная энергия.
6. Сохраните. Панель считает с момента появления сенсора в Home Assistant:
   прежние показания счётчика в статистику не попадают, первый столбец
   появится в течение часа.

Если нужного сенсора нет в списке, проверьте, что он не исключён из истории:
панель берёт данные только из записанной статистики.

## Обозначение модели

Прокси отдаёт только номер модели, а заводское обозначение Инкотекс дополняет
его буквами оснащения: `206 [P] [R|C|L] [S] [N] [O] [Fx]`. Интеграция
дочитывает у счётчика часть признаков сама, поэтому в карточке устройства
видно «Mercury 206 PRNO», а не только номер. Буквы, которых счётчик не
сообщает, в обозначение не попадают — модель просто остаётся короче.

## Ограничения

- Одна запись интеграции — один счётчик.
- Реле доступно только для чтения: прокси не умеет его переключать, поэтому
  интеграция показывает состояние реле, но не управляет им.
- Число тарифов читается при запуске записи, поэтому после перепрограммирования
  тарифов на счётчике запись нужно перезагрузить.
- Запросы идут к счётчику по одному: при периоде меньше 10 секунд они начинают
  копиться в очереди прокси.
- Поток событий прокси не поддерживает, поэтому показания обновляются опросом.
