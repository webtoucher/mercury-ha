# Счётчики Меркурий для Home Assistant

Интеграция для однофазных счётчиков Инкотекс Меркурий: активная энергия и
тарифы, мгновенная мощность, напряжение, ток и частота сети в Home Assistant,
в том числе в разделе «Энергия».

## Как это работает

Счётчик опрашивается через сервис
[mercury-proxy](https://github.com/webtoucher/mercury-proxy) — отдельную
программу или аддон Home Assistant, которая держит шину счётчика и отдаёт
показания по HTTP:

```
счётчик ── RS-485/CAN или TCP/IP ── mercury-proxy ── HTTP ── Home Assistant
```

К прокси счётчик подключается по RS-485 или CAN через последовательный порт
либо по TCP/IP, если у модели есть сетевой интерфейс: в конфигурации прокси
вместо `/dev/ttyACM0` указывается адрес вида `192.168.0.2:5051`. Для интеграции
транспорт не важен — она видит только HTTP API прокси и одинаково работает
со всеми моделями.

Прямое подключение счётчика к Home Assistant не поддерживается: интеграция
не работает ни с последовательным портом, ни с TCP/IP-интерфейсом самого
счётчика, ни с оптической головкой — рядом всегда нужен mercury-proxy,
установленный отдельно или в виде аддона.

Прокси не занимает шину монопольно. Он отдаёт REST API на порт 5054 для
интеграции и TCP-шлюз на порт 5053 для конфигуратора Инкотекс, поэтому
конфигуратор может подключаться к счётчику по TCP/IP параллельно с опросом
из Home Assistant — отключать интеграцию для настройки не нужно.

## Что появляется в Home Assistant

Одно устройство «Mercury 37793503» — по одному на каждый счётчик. В карточке
устройства модель указана полным обозначением, например «Mercury 206 PRNO».
Подписи сущностей переводятся на язык интерфейса, а `entity_id` собирается из
латинского имени устройства и ключа, поэтому он не зависит от языка и всегда
имеет вид `mercury_<серийный номер>_<ключ>`:

| Сущность | `entity_id` | Единица | Назначение |
| --- | --- | --- | --- |
| Активная энергия | `sensor.mercury_37793503_active_energy` | кВт·ч | сумма тарифных аккумуляторов, растёт монотонно |
| Тариф N | `sensor.mercury_37793503_tariff_1` … `_tariff_4` | кВт·ч | накопленная энергия тарифа, только при нескольких тарифах |
| Мощность | `sensor.mercury_37793503_power` | кВт | мгновенная мощность в нагрузке |
| Напряжение | `sensor.mercury_37793503_voltage` | В | напряжение в нагрузке |
| Сила тока | `sensor.mercury_37793503_current` | А | ток в нагрузке |
| Частота сети | `sensor.mercury_37793503_mains_frequency` | Гц | частота в сети |
| Реле | `binary_sensor.mercury_37793503_relay` | — | включено ли реле (только если оно есть у счётчика) |

Сенсор `sensor.mercury_37793503_active_energy` имеет `device_class: energy` и
`state_class: total_increasing`, поэтому его можно сразу добавить в раздел
**Энергия** как потребление из сети: *Настройки → Дашборды → Энергия →
Добавить потребление из сети* и выбрать этот сенсор. Он же подходит для
расчёта стоимости, если задать тариф.

## Тарифы

Число тарифов интеграция спрашивает у счётчика при запуске: их может быть
от одного до четырёх (день, ночь, пик). Если тарифов больше одного, на
каждый создаётся сенсор «Тариф N» с накопленной энергией этого тарифа —
их тоже можно добавить в раздел «Энергия», чтобы считать стоимость по
разным тарифам. При единственном тарифе отдельный сенсор не создаётся:
сумма и есть тариф.

## Обозначение модели

Прокси отдаёт только номер модели — `206`. Заводское обозначение Инкотекс
дополняет его буквами оснащения: `206 [P] [R|C|L] [S] [N] [O] [Fx]`.
Интеграция собирает их сама и показывает модель вида «Mercury 206 PRNO»:

- `P` — профиль мощности: счётчик хранит получасовые срезы (`get_archive_type` = 2);
- `R` или `L` — интерфейс RS-485 или PLC-модем — из `features` паспорта;
- `N` — электронная пломба: счётчик знает время вскрытия крышки
  (`get_last_cover_open_datetime`);
- `O` — силовое реле — из `features` паспорта.

Буквы, которых в паспорте прокси нет (`C` для CAN, `S` для внутреннего
питания интерфейса, `Fx` для радиомодема), в обозначение не попадают.
Неудачный запрос не мешает запуску: обозначение просто остаётся короче.

## Оформление

Иконка и логотип лежат в `custom_components/mercury_proxy/brand/`: знак
срисован с фирменного логотипа Инкотекса. Подложка иконки полупрозрачная,
поэтому картинка читается и на светлой, и на тёмной теме, а для тёмной темы
рядом лежит `dark_logo.png` со светлым знаком. Иконки сущностей —
в `icons.json`. Home Assistant берёт картинки из папки интеграции так же,
как у встроенных: они видны в списке интеграций, на карточке устройства
и в HACS.

## Языки

Подписи сущностей лежат в `custom_components/mercury_proxy/translations/`:
`en.json` — базовый, `ru.json` — русский. Home Assistant берёт файл по языку
интерфейса, поэтому в русской установке сенсоры называются «Активная
энергия» и «Напряжение», а в английской — «Active energy» и «Voltage».
`entity_id` при этом не меняется: Home Assistant собирает их из английских
подписей, чтобы id оставались прежними при смене языка.

## Установка

Сначала нужен mercury-proxy: аддон из репозитория
[hassio-addons](https://github.com/webtoucher/hassio-addons) или отдельный
сервис со страницы [mercury-proxy](https://github.com/webtoucher/mercury-proxy).
Интеграция обращается только к его REST API.

### HACS

1. HACS → Интеграции → меню → «Пользовательские репозитории».
2. Добавить `https://github.com/webtoucher/mercury-ha` с типом «Интеграция».
3. Установить и перезапустить Home Assistant.

### Вручную

Скопировать папку `custom_components/mercury_proxy` в
`<конфигурация>/custom_components/` и перезапустить Home Assistant.

## Настройка

*Настройки → Устройства и службы → Добавить интеграцию → Mercury*:

1. Адрес прокси вместе со схемой, например `http://hm.webtoucher.ru:5054`.
   Схему можно не писать — подставится `http://`.
2. Токен доступа (тот же, что в заголовке `Authorization: Bearer …`).
3. Счётчик, если к прокси подключено больше одного.

Период опроса меняется в настройках записи (по умолчанию 60 секунд,
допустимо от 10 до 3600). Если прокси перестанет принимать токен,
Home Assistant предложит ввести новый — запись при этом переиспользуется.

## Ограничения

- Одна запись интеграции — один счётчик.
- Реле доступно только для чтения: драйвер `mercury_v1` в mercury-proxy
  умеет лишь опрашивать счётчик, команд записи реле в нём нет, поэтому
  включать и выключать его из Home Assistant нельзя.
- Число тарифов запрашивается один раз при запуске записи, поэтому после
  перепрограммирования тарифов на счётчике запись нужно перезагрузить.
- Буквы модификации определяются по косвенным признакам: профиль мощности —
  по глубине архивов, пломба — по времени вскрытия крышки. Если таких
  команд счётчик не поддерживает, обозначение остаётся короче.
- Опрос идёт последовательно пятью командами; при периоде меньше
  10 секунд запросы начинают копиться в очереди прокси.
- Счётчик опрашивается по требованию, поток событий прокси не поддерживает.

## Разработка

Интеграция живёт в отдельном репозитории, а Home Assistant для проверки
поднимается из соседнего клона `home-assistant/core`. Запускать ядро
напрямую в Windows нельзя — `homeassistant/runner.py` импортирует `fcntl`,
поэтому используется официальный образ в Docker.

```powershell
cd C:\Users\mirak\PycharmProjects\home-assistant

# каталог config\ уже содержит configuration.yaml с default_config
mkdir config -Force | Out-Null

docker run -d --name ha-dev -p 8123:8123 `
  -v "${PWD}\config:/config" `
  -v "${PWD}\mercury-ha\custom_components:/config/custom_components" `
  ghcr.io/home-assistant/home-assistant:dev
```

Интерфейс открывается на `http://localhost:8123`, интеграция ставится
через *Добавить интеграцию → Mercury*. Исходники монтируются в
контейнер, поэтому после правок достаточно `docker restart ha-dev`:

```powershell
docker logs ha-dev --follow
```

Тесты не зависят от Home Assistant: клиент API поднимает поддельный прокси
на `aiohttp`, а для самого клиента достаточно виртуального окружения
репозитория ядра.

```powershell
.venv\Scripts\python.exe -m pytest mercury-ha\tests
```
